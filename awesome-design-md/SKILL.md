# Awesome DESIGN.md Reference Library

Use this library after the user's requirements and product direction are clear.

## Workflow

1. Confirm the page purpose, target user, primary action, content hierarchy, tone, responsive needs, and technical constraints before choosing a reference.
2. Choose one or two relevant references from `design-md/`. Prefer the closest product category and interaction model, not merely the most famous brand.
3. Read the selected `DESIGN.md` and extract its palette, typography, spacing, component states, layout rules, responsive behavior, and do/don't rules.
4. Adapt the reference into an original design system for the user's product. Do not reproduce a brand's logo, copy, proprietary assets, or page one-for-one.
5. Combine the reference with the project's existing `DESIGN.md`, `PRODUCT.md`, tokens, components, and user-approved design direction. Project-specific instructions win.
6. After implementation, inspect the result at desktop and mobile sizes and verify that the visual system is consistent and accessible.

## Selection guidance

- Use `linear.app`, `vercel`, `stripe`, or `notion` for structured SaaS and portfolio directions.
- Use `apple`, `airbnb`, `nike`, or `spotify` for image-led or consumer-facing directions.
- Use `figma`, `framer`, or `webflow` for design-tool and creative-product directions.
- Use `pinterest` for image-heavy discovery layouts.

These are starting points, not prescriptions. Do not combine unrelated visual languages without an explicit reason.
