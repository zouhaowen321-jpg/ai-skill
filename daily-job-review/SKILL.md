## 🆕 投递对账（每日必做 · 用户要求 2026-07-25）

**为什么有这条**：用户经常自己手动投了岗位却忘记更新主表，导致主表失真、日报误判、HR回信没人跟。**不靠用户记忆，靠他投递时留下的机器痕迹对账。**

### 三条证据线

| 线 | 怎么取 | 强度 |
|---|---|---|
| Gmail 回执 | 连接器搜 `newer_than:Nd (subject:(投递 OR 简历 OR 应聘 OR application OR applying OR received) OR "感谢您投递" OR "Thank you for applying" OR "application has been received")` | **最强**，收到回执=一定投出去了 |
| Chrome 投递成功页 | `python3 ~/job-search-system/scripts/reconcile_evidence.py --days 3 --json` | **强**，猎聘成功页直接带 job_id |
| Chrome 申请表/投递记录页 | 同上脚本的 `suspect` 桶 | **弱**，只能证明"动作做到一半" |

### 两栏输出（红线：绝不混为一谈）

**「✅ 确证漏记」**——有 Gmail 回执 或 Chrome 投递成功页，且主表里没有 / 状态不符。
每条给：公司 + 岗位 + 证据（哪封回执/哪个成功页+时间）+ 主表现状（无记录/状态过时）+ 建议写入的行内容。

**「❓ 疑似待确认」**——只打开了申请表、投递记录页、或只浏览了岗位详情页。
每条给：公司 + 岗位 + 看到了什么 + **一句直接问用户的话**（"泡泡玛特那个申请表你提交了吗？"）。

> **红线**：SUSPECT 一律不得写入主表，也不得在日报里表述成"你投了"。宁可漏报，不可把"只是看了看"记成"投了"——这是用户明确定的规矩。

### 对账要双向查

不只查"投了但主表没有"，也要查**"主表状态过时"**：
- 主表写"待提交/未投递"但有成功页或回执 → 实际已投（2026-07-25 实测抓到：携程 job_id 81170485、青岛云路 79569041 均为此类）
- 主表写"已投·等待"但已有拒信/HR回复 → 状态该更新
- 主表写"未投递"但 HR 已回信（如青岛朔方 2026-07-11 HR 回问意向城市）→ **这类最急，日报必须置顶**

### 写入主表的正确姿势（⚠️ 能力边界，不要承诺做不到的事）

**Drive 连接器只读，无法改格**（详见记忆 `gdrive-sheet-update-limitation`）。所以"自动补"的准确含义是：

1. 把「确证漏记」按主表 11 列格式写成 TSV：`~/job-search-system/outputs/reconcile/<日期>-confirmed.tsv`
2. `pbcopy < 该文件` 送进系统剪贴板
3. 日报里给一句可执行指令："打开主表 → 点名称框输入 `A<下一空行>` → `cmd+V`"
4. **用户粘贴后回一句确认，本轮对账才算闭环**

绝不用 Drive 连接器 `create_file` 重生成表（会换 spreadsheetId，打断定时任务和 Codex automation-2 的引用）。
写入行号必须先用 `read_file_content` 读主表算出真实最后一行，不能猜。

## 🆕 面试准备自动生成（用户要求 2026-07-25）

**触发**：Gmail 检测到面试邀约/预约/日历邀请 → 自动为该公司生成一份面试准备资料。

### 识别面试邀约（宁可多报不可漏报）

标题措辞五花八门，**不要只靠关键词硬匹配**。这些都算：
- `Schedule your interview` / `Interview Confirmation` / 日历邀请（`新版邀请函`、`更新邀请`）
- 面试邀请 / 面试通知 / 邀请您参加面试 / 约面 / 一面二面
- Greenhouse、Moka、Workday、Lever、Ashby、飞书等 ATS 发出的排期链接
- HR 直接来信约时间（可能完全没有"面试"二字）

> 教训：Third Bridge 那场的邮件标题是 "Schedule your interview" 和"新版邀请函"，**没有一封写着"面试邀请"**。漏一个面试的代价远大于多报一个。

### JD 三级溯源（生成准备资料的前提）

1. **主表备注**（最好）——Codex 逐卡核验过的职责、风险点、门槛，比原页面还干净
2. **Chrome 历史找 URL → 重新抓页面**（次好）——用于主表里没有的岗位。
   实测可用：LinkedIn 用 guest API `https://www.linkedin.com/jobs-guest/jobs/api/jobPosting/<jobId>` 可拿到完整 JD 原文，无需登录
3. **都没有** → 日报里明确写「JD 缺失，需你补一句这岗是干什么的」，**不许猜 JD 内容**

### 生成内容与红线

写入 `~/job-search-system/outputs/interview-prep/<日期>-<公司>.md`，参照
`2026-07-27-third-bridge.md` 的结构（已验证可用的样板）：

1. **⚠️ 必须用户本人拿主意的事项**（放最前面）——所在地/时区/到岗日期/口径冲突/证书时效等
2. 这岗到底干什么（JD 逐字要点 + 一句定性，如"这不是客服岗是电话销售岗"）
3. 核心问题库（8–12题，每题：骨架 + 可直接说的成稿 + 事实出处）
4. 语言准备（涉及韩语/日语岗必须给可朗读稿 + 听不懂时的确认句）
5. 风险应对（按被扣分概率排序，含求职信口径冲突）
6. 反问清单
7. 后勤清单（会议链接、时区双标、设备、**Google Meet 在中国大陆打不开这类硬阻断**）
8. 绝对红线表

**事实底座**：只能用 `~/job-search-system/profile/master-profile.yaml` + 用户本人写过的求职信（`/Users/zhw/Claude code/求职信/`）。

**必须过 john-profile-guard 核查**。核查器给 FAIL 时逐条裁定后再交付——注意核查器可能因**没拿到 JD 原文或面试邮件**而误判 JD 原句为编造，裁定时要把 JD/邮件原文作为可采信证据。

**最常见的编造类型（重点抓）**：
- 替用户编造具体细节（如"5类客户画像分别是…"，档案只记了"5类"）
- 替用户编造动机（"我一直对金融感兴趣"、"我最不喜欢营销的哪一点"）
- 暗示用户有他没有的经历（如韩语稿写"我擅长电话说服陌生人"，但他没做过电话陌拜）
- 替用户声明法律身份（国籍、工作许可、签证）
- 编造到岗日期、改动数字口径、加上他没有的证书（无雅思/四六级）

## Gmail 星标（每日必做，用户明确要求 2026-07-21）

对「需用户亲自处理」的邮件加 Gmail 星标（STARRED），让用户在收件箱一眼定位。
- **该标**：面试邀约、测评/笔试邀请或提醒、需补简历/材料、账号验证（仍有效的）、有明确 deadline 的待办、**HR 直接提问等回复的邮件**。
- **不标**：投递回执/确认、职位订阅推送、营销邮件、已过期的一次性验证码。
- **写法**：优先 Gmail 连接器 `label_thread(threadId, ["STARRED"])`；**若连接器返回只读/需重连权限**（2026-07-24 起为此状态），改用 claude-in-chrome：`#all/<threadId>` 打开邮件→点日期右侧星标图标→放大确认变金色。连接器只读时在日报注明「需重连 Gmail 写权限」。
- 凡进入日报「⏰倒计时」「📬状态变化」的待办邮件，必须同时星标；已星标的不重复标。

## 日报格式（一张纸原则）

```
📋 求职日报 <日期>
── ⏰ 倒计时（测评/面试/截止，48小时内置顶加粗——历史上已废3个测评，红线）
      面试项附「准备资料已生成 → 路径」
── 🎯 今日推荐（90+，各带：分数/理由/风险/应届影响/🚀快线标/简历版本/HR私信/链接）
── 🔁 投递对账
      ✅ 确证漏记（含待粘贴 TSV 路径 + 粘贴指令）
      ❓ 疑似待确认（每条一句直接问用户的话）
── 📬 状态变化（HR已查看/约面/拒绝，来自主表+Gmail回执）
── 🔧 产线健康（雷达/Codex主表全职线/日报三线是否真跑了；静默失败立即报警）
── ✅ 待你动作（勾选投递清单 + 需要人工的事项）
```

## 纪律

- 投递发送永远用户手动；日报只备料（话术+链接+开页指引）
- 用户勾选后：按 job-fit-and-tailor 分层备料 → john-profile-guard 核查 →（高分岗）Codex 二审 → 交付
- 「已投递」状态：**有 Gmail 回执或投递成功页即可判定为确证**；SUSPECT 一律等用户确认
- 主表写入只走 pbcopy TSV + Chrome 粘贴，绝不用连接器重生成表（会换 ID）
- 推送失败或 Remote Control 断线时：日报照常落盘，用户回来看文件
- 停止条件：用户说「找到工作了/停」即停用定时任务
